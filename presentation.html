STAYE
Hotel booking platform
Project overview

Staye

A modern hotel booking and listing platform designed for guests and property admins, combining browsing, secure booking, and host management in one system.

2 user roles
8+ core screens
Full stack app

System purpose

Guests can discover stays, choose room categories, reserve rooms, pay securely, receive notifications, and save receipts, while administrators manage listings, room inventory, client bookings, verification, and revenue.

Built with React + Vite on the frontend and Express + MongoDB on the backend, with Paystack payments and protected role-based workflows.

KEY FEATURES
Guest experience

Customer journey

  • Search & discovery
    Users browse listings by location, room category, price, amenities, and popular destinations.
  • Room-aware booking
    Guests choose Classic, Deluxe, Suite, or other room categories with independent pricing and availability.
  • Payments & receipts
    Paystack handles payment flow, while paid bookings expose a printable receipt with a public booking reference.
  • Notifications
    Users receive booking, payment, cancellation, and refund updates through an in-app notification center and popup alerts.
  • Secure booking
    Guests reserve rooms only through authenticated flows, reducing unauthorized access.
  • Booking history
    Users can track their reservations, status, and trip details from a personal dashboard.
  • Profile management
    Customers manage account settings and personal details within the application.

Admin workflow

  • Listing management
    Admins create, update, and monitor property listings and room availability.
  • Room inventory
    Hosts manage room categories, descriptions, amenities, prices, and available units separately from listing details.
  • Booking oversight
    The admin dashboard consolidates bookings, occupancy, and payment activity.
  • Booking verification
    Admins verify public STY booking references against their own listings and payment state.
  • Host notifications
    Admins receive alerts for new bookings, payments, failed payments, cancellations, and refunds.
  • Revenue analytics
    The platform reports revenue by currency and tracks booked rooms.
  • Protected access
    Administrative routes are separated behind dedicated authentication rules.
ARCHITECTURE
System design

Frontend

React + Vite + Tailwind CSS
Single-page application with route-based pages

Backend

Express.js API with REST endpoints for auth, listings, bookings, and payments

Database

MongoDB using Mongoose models for users, listings, bookings, and profiles

Core services

  • Authentication and authorization with JWT-based user protection.
  • Listing pages, filters, and room data retrieval from the backend API.
  • Room-aware availability, booking transactions, Paystack verification, and payment webhooks.
  • In-app notification persistence with unread counts, popup alerts, and role-specific destinations.

Environment setup

  • Frontend connects through configured API base URLs and CORS rules.
  • Server enforces required environment variables such as MongoDB URI and JWT secret.
  • Uploaded media is served from the backend uploads directory.

TECHNOLOGY STACK
Implementation details

Frontend stack

  • React 18 for component-driven UI development
  • Vite for fast development and build performance
  • Tailwind CSS for styling and layout consistency
  • React Router for page navigation and route protection

Backend stack

  • Node.js + Express for API routing and middleware
  • MongoDB + Mongoose for users, listings, room categories, bookings, notifications, and profiles
  • JWT for authentication and admin access control
  • Multer and upload routes for property media handling
  • Paystack API and signed webhooks for payment initialization, verification, and refunds
  • Helmet and express-rate-limit for HTTP hardening and abuse protection
DATA MODEL
Persistence layer

Key domain models

  • User: authentication, roles, account metadata
  • Listing: title, location, property details, images, and amenities
  • Room: room category, description, price, amenities, images, and inventory
  • Booking: reservation lifecycle, selected room, public reference, and payment status
  • Notification: user-owned booking and payment activity with read state
  • Profile: extended personal information for customer accounts

This structure supports a realistic accommodation marketplace where guests reserve stays and hosts manage inventory and revenue.

CONCLUSION
Project value

Why this project matters

Staye demonstrates a practical end-to-end software solution for the hospitality industry, covering both customer-facing experiences and operational admin responsibilities.

It shows how a modern web application can combine product discovery, room-level inventory, transactional flows, security controls, notifications, and business intelligence in a single platform.
